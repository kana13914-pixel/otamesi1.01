## フェーズ0: 技術検証（最優先・最初に実施）

最大のリスクは「自発的な声掛け」を成立させる通知経路。ここを最初に潰す。

- [ ] 最小のPWAを作成し、ホーム画面に追加した状態で通知が届くか確認する
  - 完了条件：Pushover/ntfy経由で送った通知が、ホーム画面に追加したPWAに届く
  - 人間作業が必要：実機での通知許可操作、サービスのアカウント作成（`NEEDS_HUMAN.md`参照）
  - 実装済み（Claude）：`app/`（最小PWA：manifest、Service Worker、起動状態の表示）、`scripts/ntfy_send.py`（通知送信）。通知サービスはntfyに仮決定（D-008）
  - 自動テスト：`python3 -m unittest discover -s tests -v` → PWAの読み込み・Service Worker登録・通知経由の判定、送信内容（偽サーバー宛て）がすべて OK
  - 送信手段は2つ。どちらでもよい
    - **ブラウザ（PC不要）**：公開したPWAと同じ場所の `…/app/send.html` を開き、トピック名を入れて「通知を送る」
    - **PCのスクリプト**：`python3 scripts/ntfy_send.py init` で `.env` を作り、`APP_URL` を書いてから `send`（Pythonが必要）
  - 実機確認手順（H-001〜H-003 完了後）：
    1. 公開URL `https://kana13914-pixel.github.io/otamesi1.01/otamesi-upload/otamesi-upload/app/index.html` がPCのブラウザで開けることを確認する
    2. iPhoneのSafariで `APP_URL` を開く → 共有ボタン →「ホーム画面に追加」
    3. ホーム画面のアイコンから起動 → 「表示モード：ホーム画面アプリ（standalone）」「開いた経路：ホーム画面のアイコン」「Service Worker：登録済み」と出ること
    4. iPhoneのntfyアプリで「+」→ `.env` の `NTFY_TOPIC` を購読し、通知を許可する
    5. `…/app/send.html` を開き、トピック名を入れ、配信タイミング「今すぐ」で「通知を送る」（PCのスクリプトなら `python3 scripts/ntfy_send.py send`）→ 期待結果：数秒以内にiPhoneに「キィニチくん（検証）」の通知が届く
    6. 通知をタップ → **どこで開くかを記録する**（ntfyアプリ内／Safari／ホーム画面のPWA）。画面に「開いた経路：通知（ntfy）のタップ」と表示されるか、表示モードが standalone かブラウザ内かも記録する
  - **実機結果（2026-11-06）**：通知は届いた。タップするとntfyアプリを一瞬経由してSafariで開いた（表示モード「ブラウザ内」、開いた経路「通知（ntfy）のタップ」）。ホーム画面のPWAでは開かないため、完了条件は「通知が届く」部分のみ成立。D-009に記録、方針はH-004で判断待ち
  - 注意：通知が届く先はntfyアプリであり、PWAそのものではない。iOSではURLを開くとSafariで開く可能性が高く、その場合「ホーム画面のPWAで会話を再生する」流れが成立しない。結果は手順6で確認し、`docs/decisions.md` に記録する（判断待ち：NEEDS_HUMAN H-004）
- [ ] 通知をタップして開いた後、ボタン操作1回で音声が再生されるか確認する
  - 完了条件：タップ→画面表示→ボタン1回で音声ファイルが再生される
  - 実装済み（Claude）：画面の「声を再生（テスト音）」ボタンで `app/audio/test-chime.wav` を再生。音はPythonで合成した2音のチャイムで、キャラクター音声ではない（禁止事項に配慮）。本番の声素材は未定（H-005）
  - 自動テスト：ヘッドレスChrome（自動再生許可フラグなし）で、通知経由で開いた画面からボタン1回 →「再生完了」になることを確認済み
  - 実機確認手順：
    1. iPhoneのマナースイッチをオフ、音量を上げる
    2. 前タスクの手順5〜6で通知をタップして画面を開く
    3. 「声を再生（テスト音）」を1回だけタップ → 期待結果：チャイムが2音鳴り、「再生状態：再生完了」と表示される
    4. ホーム画面のアイコンから開いた場合でも同じく鳴るか確認する
    5. 「再生失敗: NotAllowedError」などが出たら、その表示と開いた場所（Safari／PWA）を記録する
  - **実機結果（2026-11-06）**：ボタン1回でテスト音が再生された（ntfy通知→Safariで開いた画面で確認）。問題なし。Web Push経由でPWAが開いた場合の再生は、Web Push検証タスクで改めて確認する
- [ ] 画面を閉じた状態で、指定時刻に通知が届くか確認する
  - 完了条件：アプリを完全に閉じた状態から、設定時刻±60秒以内に通知が届く
  - 実装済み（Claude）：`ntfy_send.py send --at 21:30`（時刻指定）／`--in 5m`（何分後）。予約はntfyサーバーが保持して配信するため、PWA・送信元PCとも閉じてよい。本文末尾に「（予定 HH:MM:SS）」を入れ、届いた時刻と比べられるようにした
  - 自動テスト：時刻指定・翌日への繰り越し・何分後指定・不明な書式の素通し・同時指定の拒否を偽サーバーで確認済み（12件 OK）。実サーバーへの送信はこの作業環境から外部通信できないため未実施
  - 実機確認手順：
    1. `…/app/send.html` で配信タイミング「5分後」を選んで送る（またはPCで `python3 scripts/ntfy_send.py send --in 5m`）。表示された「配信予定」を控える
    2. iPhoneでPWAとntfyアプリをどちらも上スワイプで完全に終了し、画面をロックする
    3. 送信に使ったブラウザ（Safariを含む）やPCも閉じてよい
    4. 期待結果：本文の「予定 HH:MM:SS」から±60秒以内に通知が届く。ロック画面の通知時刻と比べる
    5. 「10分後」でも同様に届くこと（PCのスクリプトなら `--at 23:00` のような時刻指定も確認できる）
    6. 結果（遅延秒数、届かなかった場合はその状況）を `docs/decisions.md` に記録する

- [ ] PWA自身のWeb Pushで、タップするとホーム画面のPWAが開くか確認する（D-010で追加）
  - 完了条件：ホーム画面のPWAで通知を許可 → サーバーから送ったWeb Pushが届く → タップでホーム画面のPWA（表示モード standalone）が開き、ボタン1回で音声が再生される
  - 予約版の完了条件：PWAを完全に閉じた状態で、予約した時刻±60秒以内に届く
  - 人間作業が必要：Cloudflareアカウント作成（H-008）、実機での通知許可と確認
  - 実装済み（Claude）：`worker/worker.js`（送信サーバー。VAPID鍵の自動生成、購読登録、即時・予約送信、毎分のCron）、PWA側の購読（`index.html` の「通知を有効にする」）、`sw.js` の通知表示とタップ処理、`send.html` の「Web Pushで送る」
  - 自動テスト：Node 13件（暗号化をブラウザ側の鍵で復号、VAPID署名、予約、認証、CORS、Service Workerの通知・タップ処理）、Python 17件。暗号化はPythonの独立実装でも復号できることを確認済み。実際のAppleのプッシュサービスへの送信は未確認（作業環境から外部通信できないため）
  - 実機確認手順（H-009・H-010 完了後）：
    1. ホーム画面のアプリを一度終了して開き直す（新しいファイルを読み込ませるため）。画面に「Web Push」の欄が出ること
    2. 「送信サーバーのURL」に `https://kiinichi-push.….workers.dev`、「合言葉」に APP_TOKEN を貼り付け、「通知を有効にする」→ 許可ダイアログで「許可」
    3. 期待結果：「Web Push：有効（送信サーバーに登録済み）」
    4. Safariで `…/app/send.html` を開き、下の「Web Push で送る」欄に同じURLと合言葉を入れる →「送信サーバーの状態を見る」で「購読：あり」
    5. 配信タイミング「今すぐ」で「Web Pushで送る」→ 数秒以内に通知が届く
    6. 通知をタップ → 期待結果：**ホーム画面のアプリ**が開き、「表示モード：ホーム画面アプリ（standalone）」「開いた経路：通知（Web Push）のタップ」
    7. そのまま「声を再生（テスト音）」を1回タップ → テスト音が鳴る
    8. 予約：配信タイミング「5分後」で送る → ホーム画面のアプリとSafariを上スワイプで終了し、画面をロック → 本文の「予定 HH:MM:SS」から±60秒以内に届くこと
    9. 結果（手順6で開いた場所、手順8の遅延秒数）を教えてもらい、`docs/decisions.md` に記録する

3点とも成立しない場合、`docs/decisions.md` に結果を記録したうえで作業を止め、`NEEDS_HUMAN.md` に方針転換の判断を依頼する（候補：通知をPushover/ntfyに完全依存する形に割り切る、またはSwiftでのネイティブ化を検討する）。
